# SecondServe build plan

## Goal

Deliver a clear, stable solo hackathon prototype for the Meta Global AI Developer Hackathon. The supplied rubric is Impact 30%, Meta AI tooling 25%, Technical depth 20%, and Demo 25%.

## Product thesis

Food rescue fails when time-sensitive surplus is difficult to match and hand off reliably. SecondServe demonstrates a cautious coordinator agent that checks listing facts, ranks eligible partners, dispatches a simulated offer, recovers when a partner cancels, and records impact only when pickup is verified.

## Demo-first scope

1. Show the recovery scenario and explain its constraints.
2. Dispatch the first offer and accept it as the recipient.
3. Cancel: demonstrate capacity release and automatic replacement offer.
4. Report pickup and verify a smaller quantity; explain that only verified quantity enters impact.
5. Show an incomplete listing held for human review.
6. Optionally show a consented Muse Spark text-to-structured-draft intake; correct the draft manually.

## Accuracy commitments

Clearly label demo identities, coordinates, distances, availability, and notification flow as simulated. Keep food units separate. Never infer food-safety facts from the model. Do not call a report, accepted offer, or model draft a rescued outcome. No emissions estimate without a local baseline.

## Remaining before submission

Rerun automated checks, rehearse the short path, record only the current build, verify public repo access in a logged-out browser, complete the organizer's submission form, and submit before the portal deadline. Do not add features that jeopardize the working demo.
